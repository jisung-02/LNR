# 개발 및 운영 가이드

이 문서는 프런트엔드 유지보수와 로컬 장비 연결을 위한 안내입니다. 빠른 실행은 [README](../README.md), 버전별 변경은 [CHANGELOG](../CHANGELOG.md)를 참고하세요.

## 실행 환경

`package.json`의 `engines.node`가 지원 범위의 기준입니다.

- Node.js 22.x: 22.22.2 이상
- Node.js 24.x: 24.15.0 이상
- Node.js 26 이상

2026-09-05 검증 환경은 macOS, Node.js 26.8.1, npm 11.19.0입니다. 테스트 도구인 jsdom과 ESLint의 요구 버전까지 반영한 범위입니다. 모든 지원 Node 버전에서 테스트했다는 의미는 아닙니다.

`npm ci`로 잠금 파일의 의존성을 설치하세요. `npm install`은 의존성을 의도적으로 변경할 때 사용합니다. 패키지 변경 시 `package.json`과 `package-lock.json`을 함께 커밋하세요.

## 화면과 상태

화면은 시작(0) → 설명(1) → 촬영(2) → 암호 입력(3) → 해독(4) → 결과(5) 순서입니다. `changePageReducer`와 `Window`에서 대응 관계를 관리합니다.

- 원본 사진은 `state.image.base64Image`에 저장합니다. 촬영 사진은 data URL, 예시 사진은 로컬 자산 경로입니다.
- 장비가 반환한 사진은 `state.image.processedImage`에 저장합니다. 로컬 미리보기에서는 사용하지 않습니다.
- `state.photoData.photoData`는 기존 `암호//////해독 문자열` 형식을 유지합니다. 이름과 형식은 기존 코드와의 연속성을 위한 것이며 실제 사진 바이트를 담지 않습니다.
- 메시지 사전의 `@@`는 선택적인 부연 설명, `##`는 설명 내부 줄바꿈입니다. 부연 설명이 없는 항목도 정상적으로 표시합니다.
- 암호는 문자열입니다. `0124`처럼 앞자리 0이 의미 있으므로 숫자로 변환하지 마세요.
- `RESET_SESSION`은 화면·사진·암호를 초기화합니다. 브라우저 저장소에는 세션을 기록하지 않으며 새로고침 시에도 초기화됩니다.

카메라는 촬영 화면에서만 요청합니다. 화면을 떠나면 스트림의 모든 트랙을 중지하고 촬영 타이머를 해제합니다. 권한 요청이 늦게 완료되어 언마운트 후 스트림이 도착하는 경우에도 중지합니다. 장비 요청 중 화면을 떠나면 요청을 취소하고 응답으로 화면이 뒤늦게 전환되지 않게 합니다. HTTP 요청 취소가 서버의 실제 장비 작업까지 취소한다는 뜻은 아닙니다.

## 실행 모드

| 설정                                   | 동작                                                       |
| -------------------------------------- | ---------------------------------------------------------- |
| `VITE_DEVICE_MODE=preview` 또는 미설정 | 사진과 해독 메시지를 브라우저에서 표시. 장비 API 요청 없음 |
| `VITE_DEVICE_MODE=hardware`            | 사진 처리 API를 호출하고 결과 화면에서 인쇄 요청 가능      |
| `VITE_API_URL`                         | 장비 API 기본 주소. 기본값 `http://localhost:8000`         |

`hardware`와 정확히 일치하는 값만 장비 모드를 활성화합니다. `.env.local`은 Git에서 제외됩니다. `VITE_` 값은 비밀이 아니며 브라우저에 노출됩니다. 개발 중 설정을 바꾸면 서버를 재시작하세요. 프로덕션에서는 빌드 시 값이 포함되므로 다시 빌드해야 합니다.

휴대전화의 `localhost`는 개발용 컴퓨터가 아니라 **휴대전화 자신**을 뜻합니다. 다른 기기에서 장비 서버에 연결할 때는 그 기기에서 접근할 수 있는 서버 주소를 지정해야 합니다. HTTPS 프런트엔드에서 일반 HTTP 서버로 요청하면 혼합 콘텐츠 정책으로 차단될 수도 있습니다.

API의 요청·응답 형식은 [README의 장비 연결](../README.md#장비-연결)에 정리되어 있습니다. 이 저장소는 서버를 제공하지 않습니다. 별도 삐삐 전송 API도 확인되지 않았으므로 실제 전송 기능이 구현되어 있다고 가정하지 마세요.

### 인쇄 제약

`GET /print/`에는 사진 ID나 작업 ID가 없습니다. 프런트엔드는 현재 서버가 준비한 작업에 인쇄를 요청할 뿐입니다.

- 장비 모드에서는 한 세션씩 사용하세요. 여러 탭·기기를 동시에 쓰면 서버의 준비된 사진이 바뀔 수 있습니다.
- HTTP 성공은 요청 수락만 의미합니다. 용지 배출·삐삐 수신 여부는 장비에서 확인해야 합니다.
- 타임아웃이나 연결 종료 후에도 서버가 이미 인쇄했을 수 있습니다. 재시도 전에 출력 여부를 확인하세요.
- 다중 사용자 운영에는 서버의 작업 ID, 중복 방지, 작업 상태 조회가 필요합니다. 현재 프런트엔드에는 이 계약이 없습니다.

## 검증 절차

```sh
npm run format:check
npm run lint
npm test
npm run build
npx playwright install chromium
npm run test:e2e
npm audit
```

`npm run format`은 파일을 수정하고, `format:check`는 검사만 합니다. `npm run test:watch`는 수정 중 회귀 테스트를 반복할 때 사용합니다.

Playwright는 `127.0.0.1:5174`에 테스트용 개발 서버를 실행합니다. 로컬에서 이미 해당 주소에 서버가 있으면 재사용하므로 다른 앱이 실행 중이지 않은지 확인하세요. 결과는 Git에서 제외된 `test-results/`에 저장되며 실패 시 trace가 남습니다. 테스트에서 생성한 카메라 영상과 거부 응답을 사용하므로 실제 카메라·프린터가 필요하지 않습니다.

2026-09-05 확인 범위:

- Vitest 8개: 부연 설명 없는 암호, 사전의 상속 속성 차단, 앞자리 0 보존, 늦게 도착한 스트림 정리, 장비 실패·재시도, 중복 요청 방지, 화면 종료 후 응답 무시, 인쇄 오류 처리, 세션 초기화.
- Playwright 4개: 데스크톱 및 모바일 Chromium에서 카메라 거부 후 미리보기 전체 흐름, 잘못된 암호 안내, 가로 넘침, 촬영 카운트다운 취소.
- 320px 시작 화면의 가로 넘침을 별도로 확인.
- 포맷·린트·프로덕션 빌드 통과. 당시 `npm audit` 보고 취약점 0건.

실제 카메라 촬영 품질, 모바일 Safari, 장비 서버의 이미지 가공, 물리적 인쇄, 삐삐 전송은 검증하지 않았습니다. 모바일 테스트는 Chromium의 기기 에뮬레이션이며 실제 iPhone 검증이 아닙니다. 취약점 검사 결과는 검사 시점의 npm 데이터베이스 기준입니다.

## 문제 해결

| 증상                             | 확인할 내용                                                                                            |
| -------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 설치 시 `EBADENGINE`             | `node --version`을 확인하고 위 지원 범위로 변경                                                        |
| 5173 포트를 사용할 수 없음       | 터미널에 표시된 대체 주소 확인. 포트 고정은 `npm start -- --port 5173 --strictPort`                    |
| 카메라가 연결되지 않음           | 브라우저·운영체제 권한, 다른 앱의 카메라 사용, localhost 또는 HTTPS 여부 확인. 예시 사진으로 진행 가능 |
| 장비 서버 연결 오류              | 서버 실행 여부, `VITE_API_URL`, 네트워크·CORS, 서버 재시작 여부 확인                                   |
| 서버가 응답하지만 사진 처리 실패 | HTTP 상태와 `output_image` 필드 확인. 접두사 없는 base64 JPEG 계약 필요                                |
| Playwright 실행 파일 없음        | `npx playwright install chromium` 실행                                                                 |
| 모바일에서 내용이 길어짐         | 세로 스크롤은 의도된 동작. 화면 전체를 축소하지 않고 글자와 버튼 크기를 유지                           |

프로덕션 결과를 로컬 확인하려면 `npm run build` 후 `npm run preview`를 실행하세요(기본 포트 4173). `dist/`가 배포 산출물입니다. 배포 서버 및 장비 서버 구성은 이 저장소에 포함되어 있지 않습니다.
